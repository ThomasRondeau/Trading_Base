This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

ML trading-strategy research tool: technical-indicator features → ML/statistical models → strategies → bar-by-bar backtest, with IBKR (TWS / IB Gateway) for data and, as a first-class goal, **paper/live trading**. The same strategy, feature and risk code must work in both backtest and live mode; don't introduce backtest-only shortcuts. All code, docstrings and logs are in English and use `logging` (no `print` in the library). Strategy write-ups live in `docs/`.

A staged refactor was carried out (bug list, target architecture, steps 0–6): `~/.claude/plans/parallel-watching-crown.md`. All steps (0–6) are done: safety-net tests, bug fixes, `quantlab/` package, live-ready core (stateless features, bar buffer, parity tests), shared execution layer (runner, router, simulated and IBKR brokers), journaled live sessions with restart and replay, CLI, mypy strict clean, pre-commit.

**IBKR safety:** never send orders to TWS. Order calls are refused unless `IBKR_READ_ONLY=false` (default true; enforced in both `IBKRClient` and `GuardedEClient`), and on a real-money account (not `DU…`) unless `IBKR_ALLOW_LIVE=true`; keep both. Settings (`quantlab/config.py`): `IBKR_HOST`, `IBKR_CLIENT_ID`, and the account choice `paper` (port `IBKR_PORT_PAPER`, 7497) or `live` (port `IBKR_PORT`, 7496): `IBKR_ACCOUNT` env, CLI `--account`, UI Configuration page; default paper. Selecting paper refuses to connect to a non-DU account. The user's live TWS (7496) is a **real-money** account with a read-only API: only data requests there, with a dedicated client id. Its API has no real-time market data subscription (error 10089): historical bars work, `reqRealTimeBars` does not. Test IBKR code with the fake `EClient` in `tests/test_ibkr.py`, never against TWS.

## Running

Python 3.10 (on this machine `python` is 3.8 — use `py -3.10`). Dependencies are in `pyproject.toml`: `py -3.10 -m pip install -e .[dev]`. Run everything from the repo root.

- Tests: `py -3.10 -m pytest` (single test: `py -3.10 -m pytest tests/test_walk_forward.py::test_expand_grid`; skip the ~80 s end-to-end backtests with `-m "not slow"`).
- Characterization baseline: `tests/test_characterization.py` backtests every strategy on frozen parquet fixtures (`tests/fixtures/`) and compares all metrics to `baseline_metrics.json`. A pure refactor must keep it green. Only regenerate (`UPDATE_BASELINE=1 py -3.10 -m pytest tests/test_characterization.py`) when a change is meant to alter results, and review the JSON diff.
- Lint/format/types: `py -3.10 -m ruff check .`, `py -3.10 -m ruff format .`, `py -3.10 -m mypy quantlab` (strict; must stay clean).
- Secrets: `MASSIVE_API_KEY` from the environment or `.env` (template `.env.example`; `.env` is gitignored).

Command line (`quantlab/cli.py`; `py -3.10 -m quantlab --help`, or `quantlab` after `pip install -e .`):

- `backtest --strategy NAME [--strategy ...] [--each] --symbol S [--symbol S2] --source yfinance|massive|ibkr|file [--file F] --days N --test-days D|--test-fraction F [--param k=v|name.k=v] [--trades CSV] [--equity CSV]` — exits are strategy params too (`--param trend.stop_atr=1.5`, `--param holding_bars=10`; no global stop / target option); strategies by name from `strategies/registry.py` (`trend`, `mean_reversion`, `arima`, `ml_hybrid`, `cascade`, `pair` with two symbols). yfinance serves ~60 days of 2-minute bars.

Conservative risk defaults (10 shares/order, 50/position, 1 % daily-loss kill switch).
- `replay --session NAME` — replays a session in the backtester; `plot --symbol S --source ...` — VWAP + support/resistance chart of one session.

## Architecture (`quantlab/`)

Flow: `strategy.fit(history)` (warms the feature buffer, trains models) → `StrategyRunner.run(feed)`: per bar, `broker.on_bar` (simulated fills) → `router.on_bar_close` (time exits, kill switch) → `strategy.on_bar` → `router.submit_entry` (risk) → `Broker`. Backtest = runner + `HistoricalBarFeed` + `SimulatedBroker` (`backtest/run.py: backtest()`); live = the same runner + `IBKRBarFeed` + `IBKRBroker` (or `SimulatedBroker` for shadow mode). There is no backtest-only trading logic.

Live sessions (`execution/ibkr/live.py: open_live_session` → `LiveSession.run/stop`): start = fit on IBKR history, pickle the fitted strategies (`runtime/session.py: SessionFiles`), run with a `Journal` and a `StateStore`; resume = reload the same pickled models, `strategy.warm(fresh history)` (no retrain), `runner.set_state`, `IBKRBroker.recover` (re-map working orders by `orderRef`, replay missed executions, report orders that ended), `runner.catch_up(missed bars)` (book advances, no decisions), position reconciliation, run.

Package `__init__.py` files are intentionally empty: always import from the defining module (`from quantlab.features.technical import SMA`).

- **data/** — `DataManager` (`collect_data_yfinance`, `collect_data_massive`, `collect_data_ibkr(client, ...)` with a CSV cache in `data_cache/`). Window convention for all sources: `(symbol, days_back, until)` = from `days_back` days ago to `until` days ago. Every source returns `schema.validate_ohlcv` output (tz-aware UTC `DatetimeIndex` named `Datetime`, float lowercase OHLCV, sorted, unique).
- **features/** — stateless `Feature`s (`base.py`): `compute(data, computed)` returns columns named from the parameters (`sma_20`, `macd_hist_12_26_9`, `bb_upper_20_2`); `inputs()` lists the features they read; `warmup` declares the history needed for exact values (EWMs use `ewm_warmup`). `FeaturePipeline` resolves inputs once (by name) in dependency order and sums warmups. Composite sets (`composite.py`) take their base indicators as constructor arguments; their `outputs` are the model input columns. `levels.py` (support/resistance) is not causal: plain functions for charts only.
- **runtime/** — `BarBuffer` (preallocated ring of the last bars) and `FeatureFeed`, which serves features to a strategy: bar by bar on the buffer (the live path), or precomputed for the whole backtest (`precompute`, batch mode, 3–9× faster). Both must give the same values: `tests/test_features.py` (causality, warmup sufficiency, parity) and `tests/test_characterization.py` (runs every strategy in both modes) enforce it. Any new feature must be causal and declare a sufficient warmup.
- **targets.py** — `ForwardTarget(horizon, kind)` (`price`, `return_pct`, `direction`, `move` with `threshold_pct` in percent); labels of the last `horizon` bars are NaN.
- **models/** — `SklearnModel(estimator, feature_columns, target, score)`: `dataset()` builds X/y via `build_dataset(..., drop_last=...)` (the look-ahead margin, must be ≥ the horizon), `fit`, `predict_row(feature_row)`, time-ordered `cross_validate` on clones. Fitting uses the estimator's `n_jobs`; single-row predictions run on one thread (live latency). `ArimaForecaster` refits on a rolling window.
- **strategies/** — subclass `Strategy` (`base.py`): declare `features()`, optionally `train(history)` for models, and implement `decide(bar)` reading `self.feed.row()` / `self.feed.latest(n)` / `self.feed.bars(n)`. The base handles start/stop, warm-up gating, `on_fill` and `get_state`/`set_state`. Strategies emit entry orders (`self.order(Side.BUY, qty)`), each carrying an `ExitPlan` (`execution/exits.py`: stop / target as a pct of the fill, a distance such as k × ATR at the signal, or an absolute price; `holding_bars`) built by `exit_plan()` from the base-class exit parameters (constructor params listed in `EXIT_PARAMS`: `stop_loss_pct` 2, `take_profit_pct` 5, in percent; `stop_atr`, `take_profit_atr`, `atr_window` 14, `holding_bars` 5) and adjustable per signal. They may ask to close their own lots (`close_positions()`); `group(orders, plan)` makes the legs of a pair one group. The router executes every exit. Strategies must use only data up to the current bar.
- **runtime/runner.py** — `StrategyRunner`: the single trading loop, single-threaded; live brokers queue network-thread events and deliver them in `broker.process_events()` (called between bars and on feed heartbeats). Records the equity curve and per-bar latency. Optional `journal` (`runtime/journal.py`: SQLite WAL; bars + events `features`/`decision`/`signal`/`order`/`cancel`/`fill`/`status`/`trade`/`equity`/`session`; `JournalingBroker` records at the broker boundary; `read_journal`) and `state_store` (`runtime/state.py`, atomic JSON after every bar). Every stateful component (portfolio, risk, router, brokers, strategies) has `get_state`/`set_state`; `tests/test_session.py` checks that a cut + restore reproduces the uninterrupted run exactly. Strategies may fill `self.diagnostics` (e.g. model predictions) for the journal.
- **analysis/replay.py** — `replay_session(dir)`: reruns the session's pickled strategies on the journaled bars with a `SimulatedBroker` and compares journals (signal agreement, entry slippage live vs simulated in bp, feature diffs, P&L, latency); `bar_differences(live, reference)` for data differences.
- **execution/** — `orders.py` (`Order` with MKT/LMT/STP, OCA group and a uuid `order_id`; `Fill`; `OrderStatus`), `broker.py` (`Broker` protocol), `portfolio.py` (cash, net positions, equity), `risk.py` (`RiskLimits`: `require_stop` (entries without a stop are refused), max order / position size, daily-loss kill switch; no stop / target values, those are per lot), `router.py` (`OrderRouter`: each entry opens a *lot* owned by its strategy with the entry's exit plan frozen in it; on fill it places that lot's OCA stop/target pair at the broker; time exit after the plan's `holding_bars`; `exit_strategy` for strategy-requested exits; groups (`Order.group_id`, a pair's legs): all-or-nothing risk check, combined-P&L stop / target checked at bar close, a wide `leg_stop` per leg at the broker, any leg closed closes the others; fills attributed by order id; lots of several strategies on one symbol coexist, the broker position is their net sum), `simulated.py` (`SimulatedBroker`: market orders fill at the next bar's open + slippage, stops/limits on high/low with gaps, stop first when both legs are touched, fees in bp).
- **execution/ibkr/** — `client.py` (`IBKRClient` EWrapper + injectable `EClient`: per-request `Event`s, locked id allocation, auto-reconnect that restores real-time bar subscriptions), `broker.py` (`IBKRBroker`: our order id as `orderRef`, fills emitted after the commission report, de-duplicated by exec id, `reconcile`), `bar_feed.py` (`IBKRBarFeed`: 5-s real-time bars → strategy bars, warm-up `history()`, multi-symbol layout with forward fill). All in UTC.
- **backtest/** — `run.py` (`backtest(strategies, training, data, ...)` → `BacktestResult` with metrics, equity, trades; positions open at the end are marked at the last close), `metrics.py` (equity-curve metrics: daily returns in New York sessions, Sharpe/Sortino ×√252, max drawdown, profit factor). Multi-symbol bars carry `<field>_<SYMBOL>` columns (`schema.bar_value`).
- **backtest/walk_forward.py** — the single place for hyperparameter search: `[train][embargo][validation][embargo][test]` folds, chosen on validation, refit on train+validation, scored once on test. Takes `strategy_factory(**params)` because a strategy instance cannot be refitted. Default objective `total_return_pct`.
- **Latency budget** — `tests/test_latency.py`: median live `on_bar` of the cascade strategy (features + 3 predictions) must stay under 100 ms.

The `quant-finance-expert` skill (`.claude/skills/`) holds domain guidance for strategy/ML validation (overfitting diagnosis, purged CV, labeling, microstructure).
